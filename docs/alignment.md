## 待與 OpenSpec 組確認

以下是閱讀 5 份 spec 時發現的模糊、缺漏或可能衝突之處。**SpecKit 組不自行假設答案**；確認後將結論移入上方決議紀錄，並在此標註「已決議（日期）」。

本檔只收「與 OpenSpec 組在重大功能性需求上可能有差異、需要討論」的項目；實作細節與設計方式（例如選檔元件用 Google Picker、OAuth scope 的選擇）不在此範圍，由各子功能的 spec／plan 自行決定。下列編號因屬實作細節或不影響功能一致而移除，其餘編號不重排（歷史內容可查 git 紀錄）：Q-01（對方 repo／commit，屬取得來源紀錄）、Q-03（訊息文字，只要求語意一致）、Q-10（兩秒量測方式，屬驗證方法）、Q-11（選檔介面與授權範圍）、Q-19（匯入時結構項目，已由 OpenSpec result-export「來源結構一致性檢查」列明）、Q-25（結果更新的標示方式）、Q-29／Q-30（CSV 時間格式、BOM、換行、保護前綴）、Q-31（授權過期的錯誤分類）、Q-32（覆寫影響的顯示細節）、Q-02（額外功能：已決議核心完成後才考慮，屆時再討論）、Q-04（定案前判錯造成的版本競爭：OpenSpec ranking-review 已規定過期版本的確認須被拒絕）、Q-06（組別憑證：OpenSpec 已要求憑證且不能只靠同名冒用，分享方式屬設計）、Q-08（倒數與公平模式各自獨立、秒數由老師指定，規格已明確）、Q-09 與 Q-33（取消與結束的狀態細節；取消時沒有作答結果，依 OpenSpec 原文處理）、Q-12（單一工作表自動選用，屬實作細節）、Q-13～Q-18（002 版面與解析細節，已有共識或屬各組實作決定）、Q-20（答案長度、換行、空白保存）、Q-21（搶答中不顯示暫估順位：OpenSpec 只要求「若顯示須標示未定案」，老師看板必要內容是各組各題已送狀況與答案）、Q-22（搶答中學生只看自己組資料，不需額外資訊）、Q-23（模式於開輪時固定、不允許切換，符合 activity-session「題目、模式與截止時間 SHALL 在開輪時固定」）、Q-24（公平模式的目前成功次數包含本輪較前題目的暫算次數，OpenSpec 已明文）、Q-26（判錯標記於關輪後公開，OpenSpec 已規定）、Q-27（CSV 欄位內容細節）、Q-28（是否成功與判錯的定義，OpenSpec 已規定）。Q-05（同一老師身分同時只能有一個存續中的活動，再建立時拒絕並要求先結束或取消前一個；不同老師的活動可並存。已定案，不與 OpenSpec 原文衝突）。目前只保留 Q-07，是縮減後的版本。
