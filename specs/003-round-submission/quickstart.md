# Quickstart 驗證指南：003-round-submission

用來證明 003 端對端可用，也是非實作者人工驗證（憲章原則 VI）的操作腳本。指令以 Windows PowerShell 為準；安裝方式與 001 [quickstart](../001-activity-session/quickstart.md) 相同。實作完成後，若實際指令與本文件不同，要在同一個 PR 更新本文件。

## 前置條件

- 已完成 001 的安裝（`.venv`、`pip install -e ".[dev]"`）。
- 002 合併前：以 dev seed 放入假題目與格數。002 合併後：用兩份真實學習單匯入（需要 002 的 `.env` 與 Google 授權，憑證只放本機）。
- 一個瀏覽器，多個分頁模擬老師與各組；同一組的第二台裝置用另一個瀏覽器設定檔或無痕視窗。

## 自動化檢查

```powershell
ruff check .
ruff format --check .
mypy
pytest                       # 含 003 的單元、架構、契約、整合測試
pytest -m perf               # 含 tests/perf/test_submission_latency.py
```

預期：全部通過；`perf` 輸出「提交 → 老師看板」「提交 → 同組另一台」各 20 次的最大延遲，都小於 2000 ms（SC-006）。在 PR 記錄日期、指令與數字。

## 啟動

```powershell
python -m lecture_quiz
```

**002 已合併、dev seed 已移除**：每題格數來自 002 的真實匯入（按「匯入學習單」→ 授權 → 選檔 → 確認匯入；Google 設定見 `specs/002-guided-notes-import/quickstart.md`）。建議固定用 002 的版面 1（`2,2,1,1`）與版面 2（整體移位的同內容）驗證。

## 真實路徑驗證（002 合併後）

1. 依 002 quickstart 以真實 Google 學習單（版面 A：課程範本；版面 B：起始列欄不同、含三格題組）各匯入一次。
2. 各做一次步驟 3～5、10，確認格數與 002 預覽一致。
3. 記錄日期、試算表（不貼網址與憑證）、結果到 `verification.md`。
