# 006 UI 重新設計（huashu-design）— 設計 spec

> 分支 `feature/28-006-ui-huashu`（自 `origin/feature/9-005-result-export` 開出）。前一版設計在 `feature/28-006-ui-refresh`（taste-skill，暖紙底＋襯線＋紅藍插畫）與 `feature/28-006-ui-signal`（未提交），本版不覆蓋它們。

## 產品是什麼
Vibe Coding 課堂搶答系統：老師匯入 Google Sheets 學習單（只取題號與每題子空格數，**沒有題目文字**），各組學生用手機搶答，老師看順位、判錯、定案，最後把搶答成功的答案寫回原學習單。只在本機跑。

## 受眾與場景
- 老師：筆電接投影機，教室後排也要看得懂「現在第幾輪、誰交了、誰贏了」。同時要能操作（開輪、關輪、判錯、定案、寫回）。
- 學生：每組 1～2 支手機，站著或坐著、時間壓力下輸入答案；要立刻知道「送出了沒、本組贏了沒」。

## 核心資訊（依重要度）
1. 活動階段（準備中→開放加入→搶答中→結果未定案→結果已定案→已結束；另有已取消）與倒數
2. 本輪題目、各組作答進度
3. 每題順位：第幾名、第幾組、狀態（搶答成功／搶答正確／答錯／搶答失敗）、理由（唯一候選／提交較早／成功次數較少／以後端接收先後決定）
4. 老師動作：判錯／撤銷、確認定案、關輪、寫回、CSV
5. 同步狀態（版本號、延遲、同步中斷橫幅）

## 情感基調
比賽的緊張感，但不是遊戲機台；投影可讀、老師一眼掌握、學生不慌。

## 輸出格式（三方向統一）
每方向一個單檔 HTML，1440 寬；同一份畫面含兩個時刻：
- 老師主控台：第 2 輪、速度模式、**結果未定案**（顯示順位、判錯動作、定案按鈕）
- 學生手機（375 寬示意）：第 4 組、第 2 輪**搶答中**、倒數、第 4 題兩格作答

## 示範資料（手寫，非系統產出）
活動代碼 K7Q2FM、組數上限 6、第 2 輪題目 Q3（1 格）、Q4（2 格）、Q5（3 格）。答案為示範用。

## 約束
- 不得在畫面上捏造系統沒有的功能（例如題目文字、積分排行）。
- 正文 ≥14px、標籤 ≥12px、對比 ≥4.5:1；投影要後排可讀。
- 選定後要落回既有 HTML 結構（section id 擴充約定、hidden 屬性、textContent 輸出），不改後端與 JS 行為。
- 不用 CDN（本機離線也要能開），字型用 Windows 內建（微軟正黑體、Bahnschrift、Consolas）。
