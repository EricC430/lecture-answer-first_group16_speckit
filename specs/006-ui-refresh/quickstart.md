# Quickstart：006 介面改版的驗證步驟

本文件是**驗證指南**，不是實作說明。每一步都要記錄日期、指令或操作，以及實際結果數字（憲章原則 VI）；沒實際做就不能打勾。

## 前置

1. 分支 `feature/28-006-ui-refresh`；`.specify/feature.json` 指向 `specs/006-ui-refresh`。
2. 依 `docs/DEVELOPMENT.md` 建好 `.venv` 並安裝 `.[dev]`。
3. 只有重新產生字型子集時才需要：`.venv\Scripts\python -m pip install ".[fonts]"`，再執行 `.venv\Scripts\python scripts/build_font_subset.py`。
4. 真實瀏覽器測試需要本機的 Chrome 或 Edge（`tests/browser/cdp.py` 會自動尋找）。

## B. 截圖檢查（人實際打開看）

1. A4 會在 `specs/006-ui-refresh/screenshots/` 產生截圖：三個頁面 × 375／768／1024／1440，投影畫面 × 1280×720／1920×1080，各主要階段。
2. 逐張打開檢查：沒有文字重疊、截斷或整頁水平捲動；狀態標籤有圖示和文字；主要按鈕一個階段只有一個。
3. 把同一流程在改版前（`git stash` 或切回 `feature/9-005-result-export`）各階段顯示的資訊項目列成清單，與改版後比對，差異數應為 0（SC-002）。

## C. 手動流程（非實作者）

啟動：`.venv\Scripts\python -m lecture_quiz`，瀏覽器開 `http://127.0.0.1:8000/`。

1. **首頁**：看到系統名稱、說明、主插圖、「老師」「學生」入口；只用鍵盤可進入兩個入口。
2. **老師頁**：建立活動 → 左欄出現活動代碼與階段進度「準備中」，右欄自動停在「匯入」。匯入學習單（可用 Google 真實路徑或測試用的假替身）。
3. 按「開啟投影畫面」：新分頁出現大字活動代碼。到教室最後一排（約 8 公尺）確認看得清楚代碼（SC-011）。
4. **學生頁**（另開兩個分頁或用手機，寬度 375px）：加入兩組。計時：第一次使用者從打開學生頁到送出第一題的時間應 ≤ 1 分鐘（SC-006）。
5. 老師開輪（2 題以上、設倒數）→ 老師頁右欄自動切到「作答看板」；學生頁出現題號導覽；投影畫面只顯示題號與倒數。
6. 學生送出：按鈕顯示「送出中」→「已送出」；故意在截止後送出，看到欄位旁的錯誤訊息。
7. 搶答中，檢查投影畫面：**沒有任何組的答案、送出狀態或數量**（SC-010）。
8. 關輪 → 老師頁切到「順位與判錯」；投影畫面出現每題結果卡片。老師判錯目前的成功者 → 投影畫面 2 秒內顯示「答錯」與「第 N 組遞補」；撤銷判錯 → 恢復。
9. 確認定案 → 結束活動 → 老師頁切到「寫回」，預覽寫回。
10. **同步中斷**：在學生頁送出前關掉後端，確認頂端出現中斷橫幅、沒有「已送出」；重啟後端後看到「活動已失效」提示。
11. **鍵盤**：只用 Tab／Shift+Tab／Enter／空白鍵／方向鍵完成老師端流程（SC-004）。
12. **老師找下一步**：在每個階段請操作者指出下一步該按的按鈕，記錄秒數（應 ≤ 5 秒，SC-007）。
13. **減少動態效果**：Windows「設定 → 協助工具 → 視覺效果 → 動畫效果」關閉後重做 6、8，畫面沒有位移或淡入。
14. **離線**：拔掉網路（不使用 Google 匯入的情況）重新開啟三個頁面與投影畫面，字體與插圖完整（SC-009）。
